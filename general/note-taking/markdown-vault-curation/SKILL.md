# markdown-vault-curation

给受约束的 markdown 笔记仓库（Obsidian vault 之类：目录同名索引文件 + 自带 linter + 仓库级指令文件）做整理、归档、索引补全、规范核对。

## 触发

- 用户在笔记仓库里发出一条整理类指令（如“整理”“反思”“归档”）。这类词的具体含义写在仓库的指令文件里（AGENTS.md / README 的约束章节），**先读它再动手**，不要凭词义猜：同一个词在不同仓库里可能要求“分类归档 + 补索引”还是“指出缺漏并征询批准”。
- 广义：给一个上面这种结构的 markdown 仓库补索引、修链接、审计附件。

## 铁律

1. **先跑仓库自带的 linter，lint 不过就不做别的整理**；报告完成前再跑一次并给出退出码。
2. **不要提交**。用户会自己 stage/commit，工作树里通常混着他们进行中的内容改动；把这些和你的整理改动混进一个提交是错误的归属。报告里给出改动清单与建议的提交信息即可。
3. **不要以“规范/统一”为名改写用户既有的写法**。确认它确实违反某条明确约束再动；无法确认就原样保留，在报告里提出。
   - 已知例外：图片方括号里的尺寸标注（`![说明|309x201](path)`）在本类仓库是允许的，不要当“非标准语法”删掉。
4. 报告只写：改了什么、验证结果、遗留项。不重放过程、不贴大段 diff。

## 流程

1. 侦察：`git status --short` 分清用户已 stage 的改动与自己的改动；读仓库指令文件；列出文档树。
2. 跑 linter（如 `python lint.py`），逐条定位到具体文件，先修 linter 报出的问题。
3. 暂存目录（如 `unclassified/`）：空则什么都不做；有内容则搬到对应模块，并同步源目录与目标目录两边的索引。
4. 审计索引**内容**，不是只查链接是否存在：
   - 每个目录都有同名索引，含 yaml `constraints`、`## 概述`、`## 文件组织`（后者列出除自己外的全部文件与子目录，附件目录除外）。
   - 描述占位（“记录内容摘要”这类）等于缺失内容：用正文标题（`grep -n '^#\{2,3\} ' file.md`）重写成一句真实摘要；新增文档入库时立刻补条目。
   - 索引里的链接常被 URL 编码（`%20`），比较前先 `urllib.parse.unquote`，否则会把已索引的文件误判成未索引。
5. 扫 linter 覆盖不到的违规：行首 `*` / `+` 写成无序列表（改成 `-`）；擅自用 `_` 加粗斜体；emoji（除非该目录 constraints 关了）；同级 `attachments/` 之外的散落附件。**行间公式里以 `+` 开头的续行不是列表**，别误改。
6. 审计附件：`attachments/` 里的文件应被同级文档引用；没被任何文档引用的是遗留物——只报告，别擅自删（可能是用户尚未写回正文的图）。
7. 收尾：重跑 linter 必须 exit 0；`git diff --stat` 只应包含预期文件（被还原的文件要从 `git status` 里消失才算真的还原）。

## 当文档示例触发了 linter 误报

- 反引号内、代码块内写出的示例链接不是真实链接。修正方向是让 checker 跳过代码，**不是**把文档里的示例改掉：把 fenced code block 与 inline code 替换成等长空白（保持字符偏移不变）后再做链接/索引检查。
- 改完双向验证：示例被忽略、而正文里的真实断链仍然报错。
- 给约束文件加例外条款时，别忘了同一份约束在仓库里常有镜像文档（如 AGENTS.md 与 README.md 重复同一段），两处都要改。

## 在既有文档里写新章节

整理之外，还常在 vault 的报告/笔记里添写一节。规则同源（不改用户既有写法），另有几条：

- 动手前**重新读目标文件**：用户可能在两次读之间改过它，编辑要基于当前文本，而不是你对它的记忆。
- 只改被要求改的那一节，其余标题与段落逐字节保持原样；改完反过来核对未被触碰的节是否仍然一致。
- **不要回退用户的改动**，哪怕它删掉了你刚写的内容。若你认为被删的内容应当保留，在回复里说明，而不是擅自恢复。
- 整段替换前先**列出该区域内的全部标题**：一次大范围替换很容易连带吞掉用户自己写的小节，事后要把不属于你改写范围的恢复回去。
- 沿用文件既有约定而不是强加你的：换行风格（先看同目录的兄弟文件）、引号风格、公式记法，改之前先量一下现状。
- 交付稿里每个数字都要有产出它的命令；产出脚本已被删掉的数字不该留在报告里。

## 工具

- `scripts/vault_audit.py`：只读审计，一次性打印未引用附件、缺索引/缺章节、未索引项、过短的索引条目描述。用法 `python vault_audit.py <vault_root>`。仓库自带 linter 是权威，这个脚本只补它不查的部分。

## 姊妹 skill

- `obsidian`：同一个 vault 的读取/检索/新建/编辑。本 skill 只管整理与规范核对，动手前先看它。
